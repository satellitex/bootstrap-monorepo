# GC Agent — 検出条件・除外規定・証拠の記録

> この文書は `.claude/agents/gc-agent.md` の Step 1 から Read される検出手順の正本である。抽出先の判定・抑制条件・PR 化は書かない（`.claude/agents/gc-agent.md` が正本）。
> 比較基準は常に `origin/main`。

## 機械検査との分担

機械検査（`pnpm harness:test`）が判定できる項目は検出しない（範囲 → `tests/harness/README.md`「検査一覧」）。本 agent は再検査せず、意味判定が要る候補だけを扱う。

## カテゴリ

走査対象を全件読み込み、次の 2 カテゴリで候補を検出する。観測可能な事実（実際の重複・実際の参照不在）だけを対象とする。

| カテゴリ            | 検出条件                                                                                                                          | 例                                                          |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| A: Cross-File 重複  | Agent ↔ Agent / Skill ↔ Skill / Agent ↔ Skill のいずれの組合せでも、2 ファイル以上に存在する 3 行以上の意味的に同一・類似ブロック | バリデーション手順、共通チェックリスト、PR 作成手順の複製   |
| B: 孤児・デッド参照 | 下記 B1〜B3                                                                                                                       | 参照元が消えた reference、実装されなかった構想の agent 定義 |

各ファイルの行数を記録する（gc-agent.md の抑制条件「サイズ閾値未達」の判定に使う）。

### カテゴリ A の同一性判定

単なるキーワード一致では「共有ルール」と断定しない。次を全て満たす場合だけ、同一・類似とみなす:

- 見出し（h2/h3）または箇条書きの文脈が同等である
- 3 行以上が語順も含めてほぼ一致している、または明確なパラフレーズ関係にある
- 同じ用語を使っていても、別文脈（別ドメイン・別フェーズ）なら除外する

意味論的に独立した記述が偶然同じ単語を含んでいるだけのケースは、候補から外す。

### カテゴリ B の検出条件

| #   | 条件                                                                                                                    |
| --- | ----------------------------------------------------------------------------------------------------------------------- |
| B1  | inbound 参照 0 件の references 配下ファイル                                                                             |
| B2  | 起動経路（skill 正本・adapter・rules・他 agent・hook / CI からの起動・委譲の記述）の無い agent 定義                     |
| B3  | 実在しない先を指すポインタのうち、機械検査の対象にならない形式（Markdown リンク、節名・見出しへの参照、説明文中の言及） |

除外規定（候補化しない）:

- `docs/harness/skills/shared/` 配下 — 複数文書から参照される共通契約であり、静的な参照数だけでは孤児と判定できない
- `references/` 配下の profile — bootstrap 時・運用時に人間が埋める PJ 固有値の置き場であり、空・少参照でも孤児ではない
- gc-agent.md 自身 — 走査対象には含めるが、提案対象から除外する
- 新規追加直後のファイル — `git log --diff-filter=A` の追加日が 7 日以内（参照元を後続 PR で追加する途中状態を誤検出しないため）
- ファイル冒頭の引用行に `> orphan-allow: <理由>` を持つファイル — 外部から直接 Read される想定等。理由の妥当性は PR レビューが担う

inbound 参照の数え方:

- 探索範囲はハーネス内に限定せず、`docs/` `.github/` `package.json` も含める（ハーネス外から Read される文書を孤児と誤判定しないため）
- basename と相対パスの両方で探索する。自己参照（自ファイル内の自ファイル名）は inbound に数えない
- B2 の「起動経路」は、名前の言及ではなく起動・委譲の記述で判定する（skill 正本の委譲指示、adapter の起動指定、rules・hook / CI 等）。責務分界表・説明表に名前が出るだけでは起動経路とみなさない。`subagent_type` による明示起動と orphan-allow 宣言は機械検査が確認するため、本 agent は機械検査に現れない経路を意味判定する
- 実運用実績（当該 agent が作成した PR / Issue の存在）が判定できないなど、判定が割れる候補は削除 diff にせず、PR body の「要判断」一覧に検出証拠付きで記載する（「実績が無い」と本 agent が断定しない）

## 検出証拠の記録

各候補について、セッション内で次を保持する。証拠が欠けた候補は候補化しない。

- 対象ファイルパスと該当行番号範囲（例: `.claude/agents/refactorer.md L80-L95`）
- 該当箇所の先頭 1 行のテキスト（照合用）
- 判定根拠（A: 語順一致 / 見出し構造一致 / パラフレーズ。B: inbound 参照の探索範囲と結果）
- カテゴリ A は比較対象の行番号範囲も記録する

## 異常系

- 走査対象が 0 件: 「検出対象なし」を報告して正常終了する
- 走査対象が 1 件: カテゴリ A は検出せず、B だけを検出対象とする

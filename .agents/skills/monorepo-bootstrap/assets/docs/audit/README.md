# audit

> この文書は `docs/audit/`（外部監査・診断レポートの置き場）の命名規約である。監査の実施手順と観点は監査を行う組織が定め、ここには書かない。

## 置くもの

第三者によるセキュリティ診断・脆弱性診断・コンプライアンス監査などの報告書と、その指摘への対応記録。

## 命名

- `YYYY-MM-DD_<topic-slug>`（日付は報告書の発行日、slug は英語 kebab-case）。1 件が複数ファイルになる場合は、この名前のディレクトリにまとめる
- 同日に複数の報告書を受領した場合は slug で区別する
- 受領した報告書は形式（PDF 等）を保って置く。要約が必要なときは、同じ名前の `.md` を並べる

## 置く前の確認

- 未修正の脆弱性の詳細を含む報告書は、リポジトリの公開範囲を確認してから置く
- credential・token などの秘匿値が含まれる場合は、伏せてから置く

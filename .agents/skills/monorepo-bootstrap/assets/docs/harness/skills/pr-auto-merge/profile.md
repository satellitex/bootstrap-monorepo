# 自動マージの導入設定

導入時にこの表を埋め、運用モデルの承認範囲と一致させる。対象ブランチに取り込まれた設定を使う。設定を変更する PR は、変更前の設定で判定する。GitHub のマージ API が固定できるのは head SHA なので、委任外の本番ブランチへの書き込みは、実行アカウントに適用するブランチ保護でも制限する。

| 項目 | 設定 |
| --- | --- |
| 委任先 | 初期値は「なし」。採用時に対象リポジトリの owner/repo と開発用の base ブランチを対で記入し、自動マージの委任を運用モデルに記録する。複数リポジトリを扱う場合も、委任済みの組を列挙する。 |
| 自動化 PR の識別 | 自動化専用の作成者・アプリと、その運用で予約したブランチ名やラベルを記入する。作成元を確かめられない PR は人の PR と同じ範囲で扱う。 |
| 依存更新 bot | 利用している bot のアカウントと、更新を再要求する手段を記入する。 |
| 人の停止の意思表示 | 完全一致の保留ラベルは `automerge:hold`・`needs-human`、接頭辞は `human:`、接頭辞の例外は `human:none`。追加ラベル、PR 本文の人間判断欄（既定は「人間に判断してほしい点」）、利用中の WIP 表記を記入する。 |
| CI・レビュー | 必須の Check Run 名または従来形式の status context 名、およびブランチ保護で求めるレビューを記入する。レビュー bot の投稿やチェック名はレビュー用の既存設定を使う。 |
| 影響判定 | 外部の利用者が依存する公開面、データ移行、管理資源の破棄・置換、導入先が禁止する機能・データ、機微情報の検査方法を記入する。該当しない項目には「なし」と記入する。 |
| 開発期間モード | 初期値は無効。有効にする場合は、反映先が開発環境に限られ外部利用者がまだ契約に依存していない対象と、期間の終了条件を記入する。終了時に起動引数からも外す。 |
| 実行の上限 | 通常は 1 実行あたり 5 時間、成功マージ数は既定 10 件・最大 20 件。各 PR のレビュー対応は 3 回、欠陥修正は 2 回まで。CI は head ごとに 1 分間隔で最大 45 分待つ。同じ実行内で一過性失敗を再実行するのは、同じ CI run につき 1 回。同期処理は PR 作成から最大 30 分。導入先の CI 所要時間・実行枠に合わせて更新する。 |
| 採番 | 公開契約の採番を採用する場合は版の正本・対象ブランチ・採番を実行する契機を版管理規定に記入する。 |

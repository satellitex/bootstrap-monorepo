# ペルソナの様式

この文書は `/persona-test`（`docs/harness/skills/persona-test.md`）の S1 で書くペルソナの様式と、リテラシーの段階の定義である。プロダクトごとの用途の傾向、人数、言語の比率は profile（`.claude/skills/persona-test/references/target-profile.md`）にあり、ここには書かない。

## リテラシーの段階

対象のプロダクトの分野での慣れを 5 段階で表す。全員の中に、段階 1 と段階 5 を必ず含める。

| 段階 | 呼び方     | 目安                                                                            | テスターの振る舞いへの効き方                                               |
| ---- | ---------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 1    | かなり低い | スマホだけを使う。この分野のサービスは初めてで、用語を知らない                  | 目立つボタンを押す。長い文章は読まない。2 回つまずくとやめる               |
| 2    | 低い       | スマホが中心。似たサービスを使ったことがある。設定や詳細な項目は触らない        | 既定のまま使う。分からない用語が続くと離れる                               |
| 3    | 中         | PC も使う。同じ分野のサービスを複数使ってきた。概念は分かるが、コードは書かない | 設定を見比べる。値段と条件を自分で確かめる                                 |
| 4    | 高い       | 道具を自分で組み合わせる。スクリプトから API を呼べる                           | ドキュメントと設定の細部を読む。自分の作業の流れに組み込めるかで判断する   |
| 5    | かなり高い | 仕事でこの種のサービスを組み込む開発者。自動化とエージェントを日常的に使う      | 仕様、制限、エラーの形、規約を読み込み、記述と実際の応答の食い違いを調べる |

API や連携の口を持たないプロダクトでは、段階 4 と 5 を「設定と管理の機能を使い込む人」「業務でこの種のサービスを選定・運用する人」と読み替える。

## 1 人分の様式

ペルソナごとに、ID（`P01` からの連番）と仮名を付け、次の 5 つを書く。

| 節                         | 書くこと                                                                                                        |
| -------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 人物                       | 年齢、住んでいる所、仕事、この分野での経験、読める言語、リテラシーの段階                                        |
| 経緯と目的                 | どこで知って来たか、何をしたいか、これまで使ってきたもの、予算と支払い手段                                      |
| 環境                       | 最初に触る端末とブラウザ、作業に使う端末、表示言語                                                              |
| 重視することと離脱の引き金 | 決め手になる点と、やめる理由になる点を、それぞれ 3〜5 個                                                        |
| 触ってもらう流れ           | 公開面で確かめること、登録、利用、支払いの手前、見返しまでを、その人の目的の順に 6〜10 個の番号付きの手順で書く |

書き方の決まりは次のとおりである。

- 実在の人物をもとにしない。名前はすべて仮名にする。
- 「触ってもらう流れ」は、機能の一覧ではなく、その人が目的のために実際にたどる順で書く。開発者には API や連携の確認を、初めての人には始め方と値段の確認を入れる。
- 支払いの手順は「確定の手前まで」と書く。確定と送金は、どのペルソナも行わない。有料の機能が無いプロダクトでは、支払いの手順と支払い手段の欄を省く。
- 結果を先に決める項目（気づきやすい点、口調、フィードバックの癖）は書かない。テスターの観察が、その記述に引っ張られるためである。
- 登場人物の年齢など、profile が入力の条件として定める事項があれば、ペルソナの目的の書き方もそれに合わせる。

## 一覧表

全員を 1 つの表にまとめ、軸の重なりを見えるようにする。

| ID  | 人物 | リテラシー | 言語 | 主な端末 | 用途 | 支払い |
| --- | ---- | ---------- | ---- | -------- | ---- | ------ |

役割、リテラシー、言語、端末、支払い手段、用途のどれかが同じ人どうしは、ほかの軸を変えて、同じ観察が重ならないようにする。

## 例

例は、オンラインのレッスンを予約する架空のサービスを想定している。

<example>
P03（仮名: ユイ）、リテラシー 2

人物

- 24 歳、大阪。販売員。日本語のみ
- スマホが中心。美容院の予約サイトを使ったことがある

経緯と目的

- 知人の投稿で知った。月額のサービスは増やしたくない
- 仕事の後に、オンラインの英会話を週 1 回受けたい。月 3,000 円まで。支払いはクレジットカード

環境

- スマホの標準のブラウザ。表示言語は日本語

重視することと離脱の引き金

- 重視: 1 回ごとの値段が分かる、予約の取り消しが簡単、スマホで操作しやすい
- 離脱: 料金の条件が読めない、登録の前にカードの情報を求められる、空いている時間が見つからない

触ってもらう流れ

1. トップを見て、自分に合うサービスかを判断する
2. 1 回あたりの値段と、取り消しの条件を探す
3. 登録する
4. 体験レッスンの空いている時間を探して予約する
5. 予約の確認を開き直し、時刻と参加の方法を確かめる
6. 予約を 1 件取り消し、条件どおりに扱われるかを確かめる
7. 利用の履歴で、かかった額を確かめる
8. 回数券の購入の画面を、支払いの確定の手前まで進める
</example>

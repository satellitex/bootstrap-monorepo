# 道具と設定の形

この文書は `/persona-test`（`docs/harness/skills/persona-test.md`）の進行役が使う道具（`scripts/persona-test/`）の使い方と、run のディレクトリ、`run.json`、feedback の形を定める。テスターが使う操作の一覧は `docs/harness/skills/persona-test/tester-brief.md` にあり、ここには複製しない。プロジェクトごとの値（ホスト、認証、文言）は profile（`.claude/skills/persona-test/references/target-profile.md`）にある。

## 道具

| ファイル                                  | 役割                                                                                                          |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `scripts/persona-test/browser-server.mjs` | ペルソナごとに独立したブラウザ（context）を持ち、操作を 1 つずつ受けるサーバー。画面なしで動く                |
| `scripts/persona-test/browser.mjs`        | サーバーへ 1 操作を送る。テスターと進行役が使う                                                               |
| `scripts/persona-test/assemble-posts.mjs` | 1 人分の feedback から、送る本文と画像を組み立てる                                                            |
| `scripts/persona-test/lib.mjs`            | 上の 3 つが共有する、ブラウザを使わない部分（設定と feedback の検査、資格情報、出力の伏せ字、本文の組み立て） |
| `scripts/persona-test/playwright.mjs`     | Playwright の解決、ブラウザの起動、端末の種類ごとの設定                                                       |

ブラウザは、人が使っているブラウザとは別に、画面なしで起動する。ペルソナごとに cookie と保存領域が分かれ、端末と言語を個別に指定でき、並列に動かせる。人のブラウザのサインインに触れないためでもある。道具は Node 22 以降と Playwright だけで動き、ほかの依存を持たない。

### Playwright とブラウザ

- Playwright は、既定ではリポジトリのルートの依存から解決する（`@playwright/test` か `playwright`）。ブラウザの統合テストを持つ workspace など、別の package に入っている場合は、環境変数 `PERSONA_PLAYWRIGHT_FROM` に、その `package.json` があるディレクトリを渡す。どこから解決するかは profile に書く。
- 既定のブラウザは Playwright の Chromium の新しい headless（`channel: "chromium"`）である。ヘッドレス用の縮小版を使わないため、取得は `playwright install --no-shell chromium` で足りる（[Browsers](https://playwright.dev/docs/browsers)）。取得のコマンドは profile に書く。
- 環境変数 `PERSONA_BROWSER_PATH` に実行ファイルのパスを渡すと、取得済みの別のブラウザで起動する。

### 起動と停止

```bash
node scripts/persona-test/browser-server.mjs --run-dir <run のディレクトリ> [--port <番号>]
node scripts/persona-test/browser.mjs <run のディレクトリ> shutdown
```

- サーバーは起動したままにし、バックグラウンドで動かす。受け口は 127.0.0.1 だけに開く。
- ブラウザが未取得だと、最初の操作で起動に失敗する。profile の取得の方法で入れる。
- 止めるときは `shutdown` を送る。プロセスを強制終了した後は、run のディレクトリの `server.json` を消してから起動し直す。
- 起動し直すと、context は保存した状態（cookie、保存領域）から復元される。スクリーンショットの番号は続きから振られる。
- 進行役がページの状態を確かめるときは、`eval <式>` で式の値を読める（例: Service Worker がページを制御しているか）。読むだけに使い、画面を変える操作には使わない。

## run のディレクトリ

一時領域に、run ごとに 1 つ作る。リポジトリの中には作らない。

| パス          | 中身                                                                                             | 書く主体       |
| ------------- | ------------------------------------------------------------------------------------------------ | -------------- |
| `run.json`    | この run の設定（下の節）                                                                        | 進行役         |
| `personas.md` | ペルソナの一覧表と、1 人ずつの様式                                                               | 進行役         |
| `reports/`    | パートごとの報告書、最終のまとめ、送る短い版（`<ID>-feedback.json`）、送信用（`<ID>-post.json`） | テスターと道具 |
| `shots/`      | context ごとのスクリーンショット（連番）                                                         | 道具           |
| `post/`       | 送る画像（`<ID>/item<n>.png`）                                                                   | 道具           |
| `state/`      | context ごとのブラウザの状態                                                                     | 道具           |
| `creds.json`  | 検証用のアカウントの資格情報。値は出力に出ない                                                   | 道具           |
| `logs/`       | 操作のログ（打った文字は残さない）                                                               | 道具           |

`shots/`、`state/`、`creds.json` には、検証用の資格情報や、画面に表示された秘密が入りうる。送るのは `post/` の画像だけにし、片付けでは人間に範囲を確かめてから消す。

## run.json

```json
{
  "contexts": {
    "P01": { "device": "win", "locale": "ja-JP", "timezone": "Asia/Tokyo" },
    "P01m": {
      "persona": "P01",
      "device": "iphone",
      "locale": "ja-JP",
      "timezone": "Asia/Tokyo"
    }
  },
  "httpAuth": [
    {
      "origin": "https://app.test.example",
      "username": "user",
      "passwordFile": "~/.config/example/password"
    }
  ],
  "credentials": {
    "email": { "template": "tester.{id}.{rand}@example.com", "public": true },
    "password": { "random": "password" },
    "pin": { "random": "digits", "length": 6 },
    "code": { "fixed": "000000", "public": true }
  },
  "state": { "dropIndexedDbKeyPrefixes": [] },
  "post": {
    "title": "<親の投稿の題>",
    "disclosure": "<AI が演じたペルソナであることと、確かめた環境を述べる 1〜2 文>",
    "labels": {
      "place": "…",
      "issue": "…",
      "why": "…",
      "ideal": "…",
      "image": "…"
    }
  }
}
```

| 欄                               | 内容                                                                                                                                                                                                                                                                                                                                            |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `contexts.<ID>`                  | context の定義。`device` は `iphone`、`pixel`、`galaxy`、`win`、`mac` のどれか。`locale` はブラウザの言語、`timezone` は任意。同じ人が端末を使い分けるときは、`persona` で束ねる（資格情報が共通になる）                                                                                                                                        |
| `httpAuth[]`                     | 検証環境にかかる HTTP 認証。origin ごとに 1 件書く。パスワードは `passwordFile` から読み、設定には書かない。認証はブラウザに渡すので、ページを経由しない要求（Service Worker の取得など）にも付く。HTTP 認証が無い環境では空にする                                                                                                              |
| `credentials`                    | 検証用のアカウントの資格情報の表（名前 → 作り方）。作り方は `template`（`{id}` はペルソナの ID、`{rand}` は run ごとの乱数に置き換わる）、`random`（`password` か、`length` 桁の `digits`）、`fixed`（検証環境が受け付ける固定の値）のどれか 1 つ。`public` を付けた値だけが出力に出て、ほかは伏せ字になる。テスターは `cred <名前>` で入力する |
| `state.dropIndexedDbKeyPrefixes` | 状態を復元するときに除く、IndexedDB の記録の key の接頭辞。鍵のオブジェクトのように保存できない値を持つ記録を指定する                                                                                                                                                                                                                           |
| `post`                           | 送る本文の文言。題、但し書き、欄の名前を持つ。道具は文言を持たず、ここから受け取る                                                                                                                                                                                                                                                              |

設定に誤りがあると、サーバーは誤りを列挙して起動しない。

## feedback の形

テスターがパート D で書く、送る短い版（`<ID>-feedback.json`）の形である。

```json
{
  "persona": "<ID> <名前>",
  "intro": "<人物の紹介>",
  "items": [
    {
      "n": 1,
      "heading": "<見出し>",
      "place": "<場所>",
      "issue": "<改善してほしい点>",
      "why": "<なぜダメか>",
      "ideal": "<理想的な振る舞い>",
      "shots": [{ "path": "<絶対パス>", "caption": "<何が写っているか>" }]
    }
  ]
}
```

| 欄        | 上限（字） | 書くこと                                                                                                                |
| --------- | ---------- | ----------------------------------------------------------------------------------------------------------------------- |
| `intro`   | 150        | 年齢、立場、何をしたい人か、リテラシーの段階、使った言語と端末を 2 文で                                                 |
| `heading` | 40         | 一言の見出し                                                                                                            |
| `place`   | 60         | 本番か検証環境かを必ず入れ、画面の名前か URL のパスを添える                                                             |
| `issue`   | 220        | 何をしようとして、何が起きたか。画面の文言は要点だけを原文で引用する。観察の回数や未確認の範囲は、末尾に（ ）で短く書く |
| `why`     | 140        | このペルソナにとって何が困るか                                                                                          |
| `ideal`   | 160        | 画面がどうなっていればよかったか                                                                                        |
| `caption` | 60         | 画像に何が写っているか                                                                                                  |

項目は多くても 8 個、画像は 1 項目に 2 枚までである。改行と強調の記号は使わない。上限の正本は `scripts/persona-test/lib.mjs` の定数で、上の表はその写しである。

## 投稿の組み立て

```bash
node scripts/persona-test/assemble-posts.mjs <run のディレクトリ> <ID>
```

- 上限を超えた欄、空の欄、無い画像があれば、直す点を列挙して何も書かずに終わる。テスターに直させてから、もう一度実行する。
- 通れば、`<ID>-post.json`（親の投稿の本文と、項目ごとの本文・画像・大きさ）と、送る画像を書く。画像が 2 枚の項目は、番号と説明を付けて横に並べた 1 枚になる（そのときだけブラウザを起動する）。
- 親の投稿は、題とペルソナ名、人物の紹介、但し書き、見出しの一覧からなる。返信は、1 行目がペルソナ名と見出しで、続けて場所、改善してほしい点、なぜダメか、理想的な振る舞い、画像の説明が並ぶ。
- `<ID>-post.json` は送り先に依存しない。チャットのスレッド、Issue とコメントなど、profile の送り先への対応づけは送る側が行う。

## はまりやすい点

| 現象                                                   | 原因と対処                                                                                                                                                                                              |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 利用の結果（画像など）だけが、どの画面にも表示されない | 表示に Service Worker を使うアプリで、Service Worker の登録や取得が通っていない。道具は Service Worker を止めず、HTTP 認証もブラウザに渡している。`httpAuth` にアプリの origin が入っているかを確かめる |
| 複数のテスターが、同じ時期に同じエラーを報告する       | 製品より先に道具を疑う。確認用の context で再現し、道具が原因なら直して、該当するパートを見直させる                                                                                                     |
| 起動し直した後、鍵をかけたデータが開けない             | 保存できない値を持つ記録が、壊れた値で復元されている。その記録の key の接頭辞を `state.dropIndexedDbKeyPrefixes` に指定し、鍵を開き直す手順（暗証番号など）をテスターに伝える                           |
| `clicktext` が、意図と違うボタンを押す                 | 同じ文言を含む別の要素が先にある。`els` で番号を取り、`click @番号` で押す                                                                                                                              |
| 生体認証（指紋、顔、パスキー）のボタンが動かない       | 画面なしのブラウザには認証器が無い。別の手段（暗証番号など）で進め、検証環境の都合としてテスターに伝える                                                                                                |
| ファイルの保存が残らない                               | 道具は、始まったダウンロードを取り消して記録だけを残す。保存の入口と案内は観察できる                                                                                                                    |
| スマホの標準のブラウザに固有の表示の崩れを拾えない     | スマホの context は、Chromium にスマホの画面の大きさと User-Agent を当てたものである。別のエンジンに固有の問題は、対象外として完了報告に書く                                                            |
| 最初の操作で「Playwright が見つからない」と出て止まる  | 解決元に Playwright が無い。profile の解決元と取得の方法を確かめ、別の package に入っていれば `PERSONA_PLAYWRIGHT_FROM` を渡す                                                                          |

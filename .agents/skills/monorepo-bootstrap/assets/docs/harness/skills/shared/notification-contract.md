# 通知の共通契約（チャット webhook）

この文書は、skill がチャットの incoming webhook へ通知を送るときの共通契約（送信先の解決順、未設定時の扱い、資格情報の扱い、送信結果の扱い、疎通確認）の正本である。通知の文面・宛先マッピング・各 skill の通知条件は書かない（各 skill 文書とその profile が担当する）。

通知を使う skill は、通知の Step で本ファイルを Read し、その契約に従う。skill 固有の差分は、通知の区分（下記の「通知の 2 区分」のどちらか）の宣言と、文面・宛先だけにする。

## 送信先の解決順

webhook URL は次の順で最初に見つかった値を使う。どこにも無ければ「未設定」とする。

1. skill 固有の環境変数（任意。`PROJ_<SKILL>_NOTIFY_WEBHOOK_URL` の形。導入済みの変数がある skill は、その名前を引き続き使う）
2. 共通の環境変数 `PROJ_NOTIFY_WEBHOOK_URL`
3. プロジェクトルートの `.env`（git 管理外）にある同名のキー

worktree や無人 run では `.env` が存在しない場合があるため、環境変数を先に見る。キー名は `.env.example` に値を空にして載せ、必要な環境変数であることを示す。skill 固有の変数は、通知先を skill ごとに分けたいときだけ設ける。

## 通知の 2 区分と未設定時の扱い

通知を使う skill は、自分の通知がどちらの区分かを文書で宣言する。未設定時の扱いは区分で決まる。

| 区分 | 該当する通知 | 未設定のとき |
|---|---|---|
| 情報通知 | 完了通知など、送れなくても人間の判断が止まらないもの | 通知をスキップし、設定手順を報告に添えて正常終了する |
| エスカレーション通知 | 人間の判断が要り、console 出力だけでは自動実行時に取りこぼされるもの | 通知をスキップしたうえで、理由を明示して失敗扱いで終了する |

エスカレーション通知を失敗扱いにするのは、未設定のまま正常終了すると、判断が要る事象が誰にも届かないまま run が成功に見えるためである。

## 資格情報の扱い

webhook URL は、投稿権限を持つ資格情報として扱う。

- URL は送信先としてのみ使う。payload、標準出力・標準エラー、完了報告、PR / Issue の本文、コミット、ログに含めない
- 送信コマンドの冗長出力（`curl -v`、`set -x` など）は、URL が出力に混ざるため使わない。応答の本文とステータスだけを検査する
- profile や docs には、実値ではなく、環境変数名と通知先（サービスとチャンネル名）だけを書く

## 送信結果の扱い

- サービスが規定する成功応答でなければ、送信に失敗したものとして完了報告に明記する
- 通知の失敗で、本体の成果（PR・commit・Issue）を巻き戻さない。エスカレーション通知の送信失敗は、本体の成果を保ったまま失敗扱いで終了する

## 疎通確認

webhook の発行と URL の環境変数への投入は、秘密値の挿入にあたるため人間が行う（承認モデル → `docs/harness/OPERATING_MODEL.md`）。skill は投入を自律で行わない。投入後は、人間が 1 回テスト送信して届くことを確認する。確認の手順は、通知を使う skill の profile に書く。

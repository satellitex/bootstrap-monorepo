# PR レビューコメントは批判的に評価する

> この文書は team-shared rule の 1 つ。レビューコメント対応の判断規範のみを定め、対応フローの具体手順は `docs/harness/skills/handle-review.md` に書く。

PR レビューコメント（人間レビュアも bot レビュアも）は鵜呑みにせず、対応可否を判定してから動く。「対応しない」も正当な判断結果である。

## Why

レビューコメントに盲目的に対応すると、既存パターンとの不整合や不要な scope 拡大、技術的に正しくない変更が混入する。レビューは仮説提供であり、最終判断は実装者側の責務。

## How to apply

各レビューコメントについて、対応する前に以下 4 観点を検証する:

1. **フレームワーク / ライブラリのベストプラクティスとの整合性** — 公式 doc・ADR・既存 coding_guide に照らして妥当か
2. **既存コーディングスタイルとの整合性** — 同等パターンの既存実装との一貫性が保たれるか
3. **技術的正確性** — コメントの前提・主張が事実か（誤検出でないか）
4. **スコープの妥当性** — 対象 Issue / PR の scope を超えていないか（[scope-boundary](./scope-boundary.md) 参照）

判定結果は次のいずれか:

- 採用: 修正を実装してコミット
- 部分採用: 該当部分のみ採用、残りは判断理由を返信
- 不採用: コメントに判断理由（ベストプラクティス参照や scope 外理由）を返信して close
- 切り出し: scope 外の場合、別 Issue として追跡（[scope-boundary](./scope-boundary.md) の手順）

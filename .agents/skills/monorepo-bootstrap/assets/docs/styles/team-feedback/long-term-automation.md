# 長期的自動化を最優先する

> この文書は team-shared rule の 1 つ。実装・提案時の判断規範のみを定め、個別の自動化手段の実装手順は各 skill 正本に書かない。

実装・提案は「中長期的に人間の手元作業が減る自動化案」のみを検討対象とする。「今すぐ楽に終わる短期案」は選択肢から除外する。

## Why

短期的に楽な実装を暗黙的に積み上げると、手作業の運用負担が累積しプロジェクト全体の正味コストが上がる。「両案を並べて比較する」スタイルだと結局短期案が採用されやすく、判断負担も増えるため、最初から自動化案のみを複数パターン提示する方針に倒す。

## How to apply

- 提案時は「自動化される案」を複数パターン（hook で完全自動 / CI で gating / skill 化 / agent 委譲 / scheduled task 等）考案し、それぞれの初期コスト・運用後の手作業削減量・保守コストを比較する。短期で楽なだけの案は選択肢に入れない
- 手作業ステップ（手動コマンド・手動確認・手動コピペ・「毎回〜してください」型の運用ルール）を含むワークフローを提案しない。必ず hook / CI / skill / agent / scheduled task のいずれかに置き換える
- 一時しのぎの workaround は以下のいずれかを満たす場合に**限り**許容する:
  - 恒久対策が既存の Issue で追跡されている（該当 Issue を明示する）
  - 明確に scope 外で、別途新規 Issue として追跡可能化する（[scope-boundary](./scope-boundary.md) 参照）
  - 上記いずれも満たさない場合、workaround を提案せず恒久対策を実装する
- バグ修正・レビュー指摘対応では再発防止の自動化（lint rule / hook / test / scheduled check）を必ず伴わせる
